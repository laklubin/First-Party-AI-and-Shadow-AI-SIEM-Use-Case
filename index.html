How to read this. Each entry is a detection use case, not a finished rule. The log sources name the telemetry the detection depends on — if you do not have it, the use case is a gap to close before it is a rule to write. The sample log is a representative, synthetically generated event in the shape that source actually emits (Entra ID / M365 unified audit JSON, CloudTrail, Zscaler NSS, Netskope, Defender for Endpoint advanced hunting, Kubernetes audit, LLM gateway JSON, and so on); field names follow each vendor's schema so you can map them, but values are fabricated — no real tenant, user, key or host appears anywhere in this library. Tune every threshold to your own baseline. Framework mappings to OWASP Top 10 for LLM Applications (2025) and MITRE ATLAS are indicative, added to help you align this content with an existing threat model; neither framework publishes a native log-source taxonomy the way MITRE ATT&CK for Enterprise does.
